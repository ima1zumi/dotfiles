# Neovim Tutor

Git リポジトリで `:TutorStart` または `:TutorStart claude` を実行すると、右側の terminal に学習用の Claude Code を auto mode で起動します。Codex を使う場合は `:TutorStart codex` を実行します。CLI は事前にインストール・認証しておいてください。Neovim 0.11 以降を想定しています。

## Claude Code での使い方

1. 学習するリポジトリのファイルを Neovim で開きます。
2. `:TutorStart` を実行します。初回に CLI の認証や信頼確認が表示された場合は対応してください。
3. Claude Code の最初の質問に答え、取り組む課題や困っていることを伝えます。`learning.md` に前回の記録がある場合は、それを踏まえて続きから始めます。
4. `<C-\><C-n>` で terminal の入力から抜け、`<C-w>h` などでコードのウィンドウに移動します。
5. コードを書いて保存したら、`:TutorStart` で同じ会話に戻り、差分の確認を頼みます。

キーマップは追加しません。起動後は普通に会話してください。

- 「今日は Ruby の二分探索を学びたいです」と目標を伝えます。
- 自分でコードを書いて保存し、「今の Git 差分を見て、ヒントを一つください」と頼みます。
- 「この入力なら 3 が返ると予想しましたが、実際は nil でした」と予想と結果を伝えます。
- 区切りに「理解できているか、少し条件を変えた問題を出してください」と頼めます。

terminal から Neovim の操作に戻るには `<C-\><C-n>` を押します。`:TutorHide` で会話のウィンドウを閉じ、同じ場所で同じ `:TutorStart` を実行すると会話に戻れます。通常のウィンドウ移動も使えます。会話は `learning.md` を置いたディレクトリと CLI の組み合わせごとに保持します。

CLI を終了したり terminal バッファを削除したりした後は、新しい会話が始まります。Neovim 終了後の自動復元はありません。

Claude Code は `--permission-mode auto`、Codex は `--sandbox read-only` で起動します。Claude Code を読み取り専用に制限する構成ではありませんが、学習用の初期指示では、`learning.md` への記録を除いてファイル編集や commit を行わないよう伝えます。CLI の通常の認証・信頼確認・承認画面には手動で対応してください。設定変更前から開いている会話には新しい起動オプションが反映されないため、CLI を終了してから起動し直してください。

Neovim で最後に操作していたファイル、カーソル位置、未保存の変更があるかどうか、LSP の診断は、`stdpath("state")/tutor/` の状態ファイルに書き出し、AI に場所を伝えます。そのため「16 行目のエラーはなぜ？」のようにファイル名を省いて聞いても、AI はどのファイルの話かを判断できます。状態ファイルは、バッファやウィンドウの移動、カーソルの停止、保存、診断の変化のたびに更新し、会話を終えると削除します。Claude Code には `--add-dir` でこのディレクトリの読み取りを許可しています。

AI がファイルの中身として読めるのは保存した内容です。未保存の内容、選択範囲、テスト出力は送信しません。差分の監視や自動レビューも行いません。必要な出力は会話に貼り付けてください。

学習方針は隣の `prompt.md` にまとめています。変更は次に起動する新しい会話から反映されます。題材ごとの記録は AI が `learning.md` に残します。

会話は明るく好奇心旺盛で、好きなことや挑戦を応援してくれる、対等な友達のような雰囲気にしています。作りたいものに興味を持ち、発見を一緒に喜びながら、小さな一歩を考える方針です。ヒントは穴埋めや答えの雛形ではなく、どこに注目するか、どう確かめるかを問いかける形で出します。文法や標準ライブラリの使い方のような、考えても導けない知識で詰まっているときは、問いかけにせずそのまま教えます。疲れているときは落ち着いた調子にし、説明がほしいときは質問だけを繰り返さず答えます。口調や会話例も `prompt.md` で調整できます。

## learning.md

`learning.md` は、Tutor の AI がよりよく教えるために書く記録です。学習者の目標、理解できていること、つまずいたところ、効いたヒントの出し方、次回の続きなどを残します。次に会話を始めたとき、AI は最初にこのファイルを読んで、前回の続きから教えます。

`sandbox/書名` のように題材ごとにディレクトリを分けている場合は、それぞれのディレクトリに `learning.md` を置けます。`:TutorStart` を実行すると、開いているファイルのディレクトリからリポジトリのルートに向かって `learning.md` を探します。見つかった場合は、そのディレクトリを会話の単位にし、CLI もそこで起動します。見つからない場合は Neovim の作業ディレクトリ（`:pwd`）で起動し、取り組む内容を話したあとに、AI がディレクトリ構成を見て置き場所を決めて作ります。

`learning.md` を作った直後は、作る前と同じ会話が続きます。次に `learning.md` のあるディレクトリのファイルから `:TutorStart` を実行すると、そのディレクトリ用の新しい会話が始まります。

AI は目標が決まったときや、理解できたこと・つまずきが解決したときなどの区切りで記録を更新し、更新したことを会話で伝えます。学習者も読めるファイルなので、課題の答えや学習者を評価する書き方は残さない方針にしています。自分で書き換えても構いません。Codex は読み取り専用で起動するので、ファイルは作らず、記録したい内容を会話で伝えるだけになります。

この dotfiles では、グローバルの除外設定（`core.excludesFile` が指す `.gitignore_global`）に `learning.md` を入れています。そのため、どのリポジトリのどの階層にある `learning.md` も `git status` に出ず、各リポジトリの `.git` や共有の `.gitignore` を変更する必要はありません。除外されているかは `git check-ignore -v learning.md` で確認できます。すでに追跡されているファイルは、除外設定があっても追跡されたままです。記録を commit したいリポジトリでは、`git add -f learning.md` で追加してください。

Git の除外設定は AI からファイルを隠す設定ではありません。除外した `learning.md` も AI は直接読み書きします。
